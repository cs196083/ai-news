# 뉴스 수집기 기능 개발 워크플로

뉴스 수집기 앱에서 새 기능을 개발할 때 쓰는 명령입니다.
브랜치 이름: $ARGUMENTS

아래 단계를 순서대로 실행해.

## 1. 현재 상태 확인
- `git status`와 `git branch --show-current`로 현재 브랜치와 작업 트리 상태를 확인해.
- 기본 브랜치는 `master`다.
- 현재 브랜치가 기본 브랜치가 아니면 경고하고, 기본 브랜치로 이동할지 사용자에게 물어봐. 사용자가 동의하기 전에는 이동하지 마.
- 커밋되지 않은 변경이 있으면 알려 주고, 어떻게 할지 물어봐.

## 2. 브랜치 만들기
- `$ARGUMENTS`가 비어 있지 않으면 그 이름으로 새 브랜치를 만들고 이동해 (`git checkout -b <이름>`).
- `$ARGUMENTS`가 비어 있으면 어떤 기능을 개발할 것인지 물어봐. 답을 받으면 영어 소문자-하이픈 형식(예: `category-management`)으로 브랜치 이름을 제안하고, 사용자가 확인하면 그 이름으로 만들어.
- 브랜치를 만든 뒤 '이제 개발을 시작하세요!'라고 안내해.

## 3. 프로젝트 컨벤션 다시 안내
`CLAUDE.md`를 읽고 아래 내용을 짧게 정리해서 알려 줘.
- 기술 스택 (Next.js 16 App Router, React 19, TypeScript, Tailwind v4, Clerk, Neon + Drizzle, Gemini, Notion API)
- 개발 전 확인할 문서 (`PRD.md`, `ui.md`, `node_modules/next/dist/docs/`)
- 주요 규칙 (사용자 id로 모든 쿼리 제한, 수동 가져오기만, URL 기준 중복 제거, API 키는 서버 환경변수로만 사용, 카테고리 색상 클래스는 완전한 문자열로 작성)
- 사용할 명령 (`npm run dev`, `npm run lint`, `npx tsc --noEmit`, 스키마를 바꾸면 `db:generate` 후 `db:migrate`)

## 4. 개발 완료 처리
사용자가 '완료' 또는 'done'이라고 입력하면:
1. `git status`와 `git diff --stat`으로 변경된 파일 목록을 보여 줘.
2. 변경 내용에 맞는 커밋 메시지를 제안해 (이 저장소의 기존 커밋처럼 한국어로).
3. 사용자가 확인하면 변경 파일을 add하고 커밋해. `.env.local` 같은 비밀 파일은 절대 포함하지 마.
4. 커밋 후 기본 브랜치로 이동해서 작업 브랜치를 병합해 (`git merge <브랜치>`). 충돌이 나면 멈추고 사용자에게 알려.

## 5. 병합 후 요약
병합이 끝나면 작업 내용을 요약해서 보여 줘.
- 개발한 기능
- 변경된 파일
- 커밋 메시지와 병합된 브랜치
